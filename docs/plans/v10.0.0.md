# v10.0.0 — Continuity Studio

Status: released — tag `v10.0.0` and public GitHub Release are live; physical/manual desktop gates
remain explicitly recorded as `NOT RUN`.

## Goal

Make visual continuity a first-class local production concern. A Production Bible owns characters,
locations, props, and looks; every shot records exactly which profiles and references were used.

## Boundaries

- Veo 3.1 remains the first execution target and is constrained by its real reference-image limits.
- Reference profiles are created from local assets, accepted takes, and extracted frames only.
- Local preflight always runs. Multimodal review is optional, separately approved, and never automatic.
- Critical continuity failures block paid approval. Soft drift is a warning with an explicit override.
- Existing app identity, storage paths, deep links, project compatibility, and fail-closed pricing remain.
- Collaboration, campaign batching, new providers, AI-generated reference images, and full NLE
  rendering are outside v10.

## Completion evidence

- Migration tests cover representative v5–v9 projects, unknown fields, duplicate execution, and
  asset/provenance preservation.
- Continuity compilation is deterministic across restart and archive export/import.
- Approval rejects missing references, over-capacity references, incompatible models, and changed
  snapshot fingerprints.
- Export contains the Production Bible, bindings, snapshots, reports, and provenance.
- `npm run validate:release`, packaged smoke, schema migration, and restart recovery are recorded
  independently as `PASS`, `FAIL`, or `NOT RUN`.
